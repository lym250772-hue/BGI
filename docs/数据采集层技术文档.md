## 二、采集渠道详情

### 2.1 渠道能力矩阵

| 渠道 | Spider | 类型 | 速度 | 评论采集 | 图片采集 | 登录方式 |
|------|--------|:--:|:--:|:--:|:--:|------|
| 微博 | `weibo_api_spider.py` | 纯 HTTP | 12.8/s | ✅ `get_comments()` | ✅ pic_ids | Cookie |
| 知乎 | `zhihu_api_spider.py` ★v2.0 | 纯 HTTP | 3-5/s | ✅ `get_comments()` | ✅ image_list | Cookie (z_c0) |
| 小红书 | `xiaohongshu_spider.py` | Playwright | 0.3/s | ❌ 需签名 | ✅ image_list | Cookie (a1/web_session) |
| 抖音 | `douyin_spider.py` | Playwright | 0.4/s | ❌ 需签名 | ✅ image_list+图集 | Cookie + msEdge |
| 贴吧 | `tieba_spider.py` | Playwright | 0.03/s | ✅ _fetch_thread_detail | — | BDUSS Cookie |
| Telegram | `telegram_collector.py` | Telethon | — | — | — | API ID/Hash |

### 2.2 微博 — AJAX API 模式（最快）

**技术栈**: `requests.Session` + Cookie 注入 + JSON 解析

**API 端点**:
| 功能 | 端点 | 说明 |
|------|------|------|
| 搜索 | `weibo.com/ajax/statuses/search?q={kw}&page={p}&count={n}` | 每页20条 max |
| 评论 | `weibo.com/ajax/statuses/buildComments?id={id}&count={n}` | 游标分页 |
| 热搜 | `weibo.com/ajax/side/hotSearch` | 公开 API |

**Cookie 要求**: `SUB` 或 `SUBP`（登录后从 EditThisCookie 导出），`data/raw/weibo_cookies.json`

### 2.3 知乎 — API 模式（v2.0 新增，纯 HTTP）

**技术栈**: `requests.Session` + Cookie 注入 + JSON 解析

**API 端点**:
| 功能 | 端点 | 说明 |
|------|------|------|
| 搜索 | `/api/v4/search_v3?q={kw}&type=content&offset={o}&limit=20` | 每页20条 |
| 答案 | `/api/v4/questions/{qid}/answers?limit=3` | 含内容+投票数 |
| 评论 | `/api/v4/answers/{aid}/comments?limit=10` | 含作者+内容 |

**Cookie 要求**: `z_c0`（认证）+ `d_c0`（设备），`data/raw/zhihu_cookies.json`

**提升**: 速度从 0.2/s → 3-5/s（15-25x），无浏览器开销

### 2.4 小红书 — API 拦截模式

**技术栈**: Playwright + 请求拦截 + DOM 备用

**流程**: 打开搜索页 → 拦截 `/api/sns/web/v1/search/notes` 响应 → 解析 JSON → DOM 解析兜底

**关键字段**: `note_id`、`image_list`、`tags`、`interact_info`（like/collect/comment 数）

**限制**: 评论 API 需要 X-s/X-t/X-s-common 签名，纯 HTTP 版本需维护签名算法

### 2.5 抖音 — 首页搜索框模式

**技术栈**: Playwright + 键盘操作 + 正则文本提取

**流程**:
1. 从 `douyin.com` 首页搜索框输入关键词
2. `page.keyboard.type(keyword)` + `press("Enter")`
3. 等待搜索结果加载
4. 从 `body.innerText` 正则匹配提取：时长、点赞、描述、@作者、日期
5. 备选：`page.evaluate(fetch())` 调搜索 API

**限制**: 首页搜索绕过 URL 验证码，但无法获取 `aweme_id`（需 msToken/Bogus 签名）

**图片**: 图集帖的 `image_list` 已提取；视频帖提取 `video_cover_url`

## 三、统一数据模型（IntelItem）

所有渠道产出统一汇聚为 `IntelItem` 结构：

```python
@dataclass
class IntelItem:
    # 核心字段
    platform: str           # 来源平台
    content_raw: str        # 原始内容文本
    content_type: str       # text / video / image / comment
    source_url: str         # 原文链接

    # 作者
    author_uid: str         # 作者 UID
    author_username: str    # 作者昵称
    group_id: str           # 分组标识

    # 时间
    collected_at: datetime

    # 消息标识
    message_id: int | None

    # 媒体 ★v2.0
    image_urls: list[str]   # 图片链接列表
    video_cover_url: str    # 视频封面链接

    # 扩展
    metadata: dict          # 平台特定元数据
```

## 四、并发编排引擎（v2.0 新增）

### 4.1 `CollectionOrchestrator`

```
每平台 1 个独立线程 → 并行采集 → Queue(5000) → WritePipeline → MySQL
```

- **RateLimiter**: 令牌桶算法，每平台独立限速
- **ProgressTracker**: 线程安全实时统计，5秒定时报告
- **Checkpoint**: 每 5 页保存断点，Ctrl+C 优雅停机，下次自动恢复

### 4.2 `ConcurrentWritePipeline`

- 生产者-消费者模式，单 consumer 线程批量 `executemany`
- `Queue(maxsize=5000)` 提供背压——采集太快时自动阻塞
- 失败自动重试（指数退避，最多 3 次）

### 4.3 使用方式

```bash
# 全通道并发
python main.py collect-all -k "刷单,接码,跑分" --max-pages 3

# 指定平台+速率控制
python main.py collect-all -k "刷单" --platforms weibo,zhihu --rpm 15

# Ctrl+C 中断 → 保存断点 → 下次运行自动恢复
```

## 五、图片 & OCR 管道

### 5.1 `MediaStore`（v2.0 新增）

- 图片下载到 `data/images/{platform}/{raw_id}/` 永久存储
- MD5 去重（URL 相同 → 文件复用）
- 线程池并发下载（4 线程）
- 格式自动检测（jpg/png/webp/gif）

### 5.2 `MediaBridge`（OCR 管道）

- 从 `metadata.image_list` 提取图片 URL
- PaddleOCR 中文识别 → 写入 `dwd_clean_intel.ocr_text`
- `merged_text = content_raw + OCR文本` → 分析引擎使用

### 5.3 使用流程

```bash
python main.py collect-all -k "刷单"  # 采集（media_urls 自动填充）
python main.py clean -l 500           # 清洗
python main.py ocr -p douyin,xiaohongshu -l 100  # OCR 图文
python main.py analyze -l 200         # 分析（读取 merged_text）
```

## 六、反爬策略（BaseSpider）

| 策略 | 实现 |
|------|------|
| UA 轮换 | Mac/Windows Chrome UA 随机 |
| webdriver 隐藏 | `navigator.webdriver = false` init script |
| Cookie 注入 | EditThisCookie 格式 → Playwright add_cookies |
| 随机间隔 | 每次请求 1.5-4.0s 随机延迟 |
| 首页预热 | `start()` 先访问首页建立会话 |
| 自适应退避 | 连续空结果递增延迟(上限30s) |
| 检查点 | 每5页保存进度，支持断点续采 |
| 增量采集 | 按关键词记录最后时间戳，跳过已采集 |
